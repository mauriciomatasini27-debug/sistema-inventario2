P9-12: lista única ADMIN_ALLOWLIST_SUBS para admin y superadmin, con SUPERADMIN_SUBS como fallback deprecado.

## Decisión
Una sola lista gobierna `exigirAdmin` y `esSuperadmin`: `leerAllowlist` une `ADMIN_ALLOWLIST_SUBS` con el fallback `SUPERADMIN_SUBS`.
El parseo recorta, ignora vacíos y dedupa preservando orden (primero ADMIN, luego legacy nuevo).
Si hay legacy no vacío, un `console.warn` por proceso avisa la deprecación sin loguear subs.
`esSuperadmin` delega en `leerAllowlist`; vacía niega todo (fail-closed) en `/api/tenants` y `/api/admin/*`.
Se quitó el import muerto en `onboarding/alta.ts` y se migraron 3 tests a `ADMIN_ALLOWLIST_SUBS`.
Rojo antes: 5/6 en `tests/admin-lista-unica.test.ts` (403 con solo ADMIN, sin warn ni unión); verde 6/6 tras el fix.
Toca `guard.ts`, `control.ts`, `.env.example`, ADR-0030 y este avance; sin migración.
