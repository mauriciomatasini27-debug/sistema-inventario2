P10-101: perfil `diseno` en `.opencode/modelos-por-skill.json` para prototipos de UI mobile-first y las skills visuales, con respaldo sin retención y test que fija el mapeo.

## Decisión
- El prototipo de UI se juzga mirando el render a 360px, no leyendo el diff; el primario de `codigo` (deepseek) optimiza otra cosa y no es el mejor juez de jerarquía, espaciado o copy.
- `diseno` ordena `claude-haiku-5-5 → gemini-4-argon → gpt-6-luna → kimi-k3.1-pro → deepseek-v4.1-flash-free`: haiku abre por criterio visual y costo de iteración; los dos del medio aportan contexto largo y entrada de imagen para varias variantes; el free cierra para que la cadena siga viva sin key de Go.
- Se mapean `prototype`, `variant`, `better-ui`, `better-layout`, `better-typography`, `better-colors`, `emil-design-eng` y `build-design`; `interface-review` sigue en `juez` para cruzar familia.
- `gemini-4-argon` y `kimi-k3.1-pro` se suman a `privacidad.sinRetencion`: los prototipos llevan copy y precios del producto, y los endpoints Go no entrenan con datos por default.
- `tests/opencode-modelos.test.ts` fija que esas skills resuelvan a `diseno`, que su primario no sea el de `codigo` y que ningún eslabón pueda entrenar; el cambio deja de ser silencioso.
- Sin cambios en agentes ni en `opencode.json`: el perfil aplica solo a skills.
