P10-33: `verify` nombra el test fallido, explica los pasos omitidos y solo cita el recibo si lo escribió.

## Decisión
- `resumir` expone el motivo de cada paso omitido para poder imprimirlo inline.
- El mensaje usa "pasos omitidos: <paso> (falló <dependencia>)", sin "skips" suelto ni "motivo en el recibo".
- Cuando falla `test`, se lee `vitest-report.json` y se imprimen los nombres de los asserts fallidos.
- Si no hay nombres, se da la ruta al reporte y un comando `node -e` concreto para extraerlos.
- La línea del recibo aparece solo cuando se escribió archivo; con `--no-receipt` no se menciona.
- `verify ok (<total> pasos)`, el código de exit y la lista de pasos quedan intactos.
- El formato del reporte JSON de Vitest y del recibo no cambia.
