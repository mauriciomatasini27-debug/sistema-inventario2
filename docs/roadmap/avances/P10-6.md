Las ventas offline que llegan por `POST /api/sync/push` (`modulo: "sales"`) se aplican con `registrar_venta`: venta, ticket, `ticket_lines`, `stock_movements` y stock, idempotente por `op_id` y sin tocar la numeración T-* de promote.

## Decisión
- `src/modules/sync/aplicar-venta-outbox.ts` valida el payload con `postSalesSchema` y llama a `registrar_venta` con `key = op_id`, `offline: true` siempre (sin definitivo; lo asigna `/api/sync/promote`) y sin `gateFiscal`.
- Resultados: `YA_VISTA`/`YA_VISTA_DB` => `ya_aplicada`; payload inválido o rechazo de negocio => `no_aplicable` (la op queda en `outbox`); ok => `aplicada` con `sale_id`.
- `empujarOperacion` aplica después del 201 y también en el replay 200, así se cierra el hueco "op guardada pero venta sin aplicar". La op sensible (`necesita_conexion`) no se aplica.
- Si el aplicador lanza, el push responde 503 `venta_no_aplicada`: `sincronizarColaVenta` corta y no saca la op de la cola (VF-S2).
- En el lote `{ ops }`, una respuesta 4xx/5xx sale como `resultado: "error"` con su `status`, no como `aplicado`.
- El replay compara el payload con claves ordenadas: `jsonb` no conserva el orden y el replay de una venta daba 409 falso.
- Sin migraciones ni dependencias nuevas. El doc fiscal pendiente que arma `/api/sales` todavía no se crea para estas ventas.
