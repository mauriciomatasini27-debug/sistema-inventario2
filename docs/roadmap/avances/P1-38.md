P1-38: tras un push OK de la cola offline /venta pide el ticket definitivo con promote.

## Decisión
`POST /api/sync/promote` ya existía (ADR-0017) y los tests de HTTP lo cubrían.
La UI solo hacía push; el ticket quedaba provisorio.
`sincronizarColaVenta` acepta `promover` opcional y lo llama tras cada push 2xx.
Si promote falla, la venta no vuelve a la cola (ya está aplicada).
`/venta` cablea el fetch y el drenado muestra los `T-*` en el status.
Sin latido en este ítem.
