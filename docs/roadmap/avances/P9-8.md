P9-8: `cerrarCaja` cuenta QR fuera del try de persistencia con helper seguro que informa 0 si falla (H1 #78).

## Decisión
Root cause: `qrSinComprobante: await contarQrSinComprobante()` corría dentro del try que persiste el cierre; si el conteo lanzaba, el catch reejecutaba `cerrar_jornada` en memoria y duplicaba un cierre ya guardado en DB.
El try ahora solo cubre cheques + insert + espejo y captura `{cierre, wa}`; el conteo corre después vía `contarQrSinComprobanteSeguro()` (try/catch propio, 0 ante fallo); `conAvisoMemoria` usa el mismo helper.
Sin cambios de contrato: 201 con `fuente db` y `qrSinComprobante 0`, reintento con otra key misma fecha sigue 409 y queda una sola fila en `closing_summaries`.
Red: `tests/caja-h1-cierre-qr-count.test.ts` 3/3 fallaba (`BaseNoDisponible` desde `caja.ts:260` con DB viva multi, throw en memoria); verde tras el fix más vecinas caja 42/42 y `typecheck` limpio.
Toca `src/lib/repos/caja.ts` (cierre + helper) y el test nuevo; sin migración ni cambios de API.
