P10-26: cierre de la deuda #337 de PLAN-COM-01-B: `payeesVivos` deja de tragarse el error del select de beneficiarios.

## Decisión
El `catch` vacío de `src/lib/repos/ordenes-pago.ts` prometía que el insert diría el error real, pero el select podía fallar sin dejar rastro y la orden se preparaba con la memoria caliente.
Ahora el fallo se registra con `console.warn` y se pasa a `payeesAlm.anteFalloPersistencia(e)`, el canal que ya usa el repo para señalar degradación de la persistencia.
En multi ese canal lanza `BaseNoDisponible` y la ruta responde 503: no se prepara una orden apoyada en datos fríos cuando la base falló.
En single sigue la memoria caliente, que es la fuente de verdad monoproceso; el warn deja el rastro que antes borraba el `catch`.
No se crea ADR: no hay decisión nueva, se aplica la política de ADR-0064 a una deuda ya inventariada en `PLAN-COM-01-B`.
Los dos bordes viven en `tests/com-337-payees-select-fallido.test.ts`: multi propaga, single avisa y sigue.
La deuda se cerró en el issue #337; código y test se mergearon en el PR #409 (commit `0ae65ea`).
