El cobro de fiado es atómico entre el abono al cliente y la entrada de caja (FC5).

## Decisión
- `src/lib/repos/fiado.ts` escribe `customer_movements` y `cash_movements` (tipo "ingreso", origen "cobro_fiado") dentro de una sola `db.transaction`; si algo falla, se revierte todo.
- Se saca la llamada a `registrarIngresoCobro` del camino con base, porque abría su propia conexión y dejaba el cobro a medias ante una caída.
- El camino sin base sigue usando el espejo en memoria y falla todo o nada.
- La clave de idempotencia es la misma en las dos tablas, y una repetición responde 409.
- Verificado: `npm run verify` ok (10 pasos); `tests/tickets.test.ts` comprueba que el cobro deja la caja en +5000.
