P10-32: la guía de desarrollo local manda reutilizar el worktree canónico antes de crear otro.

## Decisión
- `git worktree list` pasa a ser el primer paso al retomar un issue o branch existente.
- Si el branch ya está checado en algún worktree registrado, se trabaja ahí; se crea uno nuevo solo si no aparece.
- La guía nombra la convención real del entorno: `worktrees/<tema>` con branch `mauri/<tema>`.
- `AGENTS.md` lleva solo un puntero de una línea a la guía, sin repetir la convención en el cuerpo.
- El flujo de un cambio referencia la sección nueva antes del `git switch -c`.
- No se agrega lógica ni comandos nuevos en `scripts/`; el cambio es documentación pura.
- No se mueven ni borran worktrees existentes.
