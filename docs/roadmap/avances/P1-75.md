P1-75: filtro db:migrate no saltea CREATE TABLE; runner sin return ilegal en Node 24.

## Decisión
`filtrarStatementsPorTablas` trataba CREATE TABLE como cualquier otro statement y lo saltaba si la tabla no estaba en `information_schema`, rompiendo 0044 en bases reales al 0043.
CREATE TABLE siempre va a `run` y la tabla pasa al set local del tag para índices y ALTER siguientes.
ALTER/INDEX sobre tablas ausentes sin CREATE previo en el mismo archivo siguen en `skip` (caso `inventory_counts` en 0043).
Tests unitarios cubren el contrato del filtro; integración PG reaplica 0044 tras simular cola al 0043.
`db-migrate.mjs` reemplazó `return` en el cuerpo top-level por `process.exit` y ramas `else`, compatible con Node 24.
`sslPostgresDesdeUrl` desactiva SSL en localhost, 127.0.0.1 y ::1; remoto sigue en require.
CREATE FUNCTION/TYPE/EXTENSION/SCHEMA siempre corren; `tablaDeStatement` no confunde FUNCTION con ON tabla.
