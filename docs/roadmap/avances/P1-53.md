P1-53: el dueño crea un vencimiento de caja y lo marca pagado desde /panel/caja.

## Decisión
El API ya daba de alta y cobraba. El dueño tenía que mandarlo con curl.
La misma tarjeta que lista pide concepto, fecha y hora, y monto. El POST manda vence_el en ISO.
El botón Pagar confirma y manda PATCH con Idempotency-Key. No manda metodo. El API usa Efectivo.
No hay GET ?id=. La lista ya trae el pendiente, así que la precarga no aporta.
Un 201 refresca la lista. Un pago refresca lista, saldo y movimientos. Un 409 dice que ya está pagado.
Retiros, reversas, export y comprobantes QR no cambian.
