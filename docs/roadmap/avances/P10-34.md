P10-34: el nombre asignado a un dispositivo se persiste en `devices.nombre` y se relee de la base del comercio.

## Decisión
#357 cerraba la deuda COM-01 del comentario de `src/lib/store.ts`: `deviceNames` era solo un Map en memoria y el nombre se perdía al reiniciar.
Se agrega la columna nullable `nombre` en `devices` con el tag `0058_devices_nombre` (SQL + journal), autorizado por Mauri y ya registrado en el repo de migraciones por #415.
El repo `device-nombres` sigue el patrón DB-first con `dbVivaTenant(tenantId)`: escribe y lee `devices` cuando hay base, y hidrata el Map como espejo.
En single sin base el Map sigue siendo la fuente y las rutas responden como antes; en multi sin base `BaseNoDisponible` se traduce en 503 `base_no_disponible`.
`nombrar` y `register` pasan a persistir el nombre; las listas de sesiones lo recuperan de DB, de modo que sobrevive a un reinicio del proceso.
La columna es nullable con default null para no romper las filas existentes y no se aplica a ninguna base real desde acá.
El tag 0058 no se registra de nuevo: su JSON ya está en `main` vía #415, y el gate de merge lo valida contra la rama base.
