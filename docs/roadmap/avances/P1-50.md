P1-50: /panel/caja revierte un movimiento con POST /api/cash/reversals.

## Decisión
El API de reversas ya existía. El dueño tenía que mandarlo con curl.
La tarjeta pide el id del movimiento, el motivo si hay y quién lo carga. El actor arranca en panel-web.
El historial muestra el id de cada movimiento para copiarlo en revierte_a.
El POST manda JSON y una Idempotency-Key nueva, después de confirmar.
Un 201 refresca el historial y el saldo, y muestra el movimiento_id.
Un 403, un 422 o un 503 se muestran con textoError.
Export, QR y el alta de vencimientos quedan afuera. Retiros, cierre y turnos no cambian.
